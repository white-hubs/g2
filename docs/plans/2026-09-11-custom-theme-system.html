G2 平台设计方案

自定义主题色系统：颜色归集与需求设计

支持用户与租户自定义主题色；由主应用集中定义，通过语义化 Token 向所有子应用统一派发。

目录 1. 目标2. 现状与颜色归集3. 主题数据模型4. 派发与运行时机制5. 页面编码规范6. 用户操作与接口需求7. 安全性与可访问性8. 分阶段实施9. 自动化约束与验收10. 决策

1. 目标

核心原则：子应用只消费语义 Token，主应用是主题唯一写入者。
支持租户或用户创建、保存、切换任意主题，并即时传递给所有 G2 子应用。覆盖页面背景、卡片、文字、边框、输入控件、表格、弹窗、按钮和基础 Ant Design 控件。
不采用按主题名称分支的实现。“开河蓝”“夜幕黑”仅作为内置主题数据，不应在子应用中出现 if (theme === 'dark')，也不应维护一份又一份 dark.css。

2. 现状与颜色归集

已有基础

  • pc-chrome/src/skin-theme.ts 已能写入 CSS 变量、持久化主题并向遗留子应用发送事件。
  • skin-theme-vars.ts 已维护部分 Ant Design 3 色板与旧组件桥接。
  • platform.ts 在主应用初始化时恢复上次主题。

当前链路主要覆盖主色。在 pc-chrome、pc-ui、security-monitor、generic-equipment-monitor 范围的静态扫描中，仍有 48 个源码文件含硬编码颜色。

归集结论相同色值在不同页面可能承担不同职责。#fff 就可能表示页面容器、输入框、弹窗、表格行或按钮文字，因此必须按照语义拆分，不能做全局字符串替换。

颜色分层

品牌色

主色与派生色阶。允许用户修改，驱动按钮、链接、选中态、焦点态。

中性色

背景、文字、边框、遮罩。允许用户修改，支持亮/暗基底与高级微调。

组件色

输入框、表格、弹窗、分页、Tabs。只映射 Token，不单独保存。

状态与业务色

成功、警告、错误、告警等级、图表序列。默认保持业务语义，高级主题可整组覆盖。

3. 主题数据模型

主题由后端保存为可版本化的 JSON，而不是仅保存 primaryColor。

interface ThemeTokens {
  primary: string; primaryHover: string; primaryActive: string;
  primarySoft: string; primaryBorder: string;

  pageBg: string; surfaceBg: string; elevatedBg: string;
  inputBg: string; tableHeaderBg: string; tableRowBg: string;
  fillSecondary: string;

  text: string; textSecondary: string; textTertiary: string;
  placeholder: string; textOnPrimary: string;

  border: string; borderSecondary: string; focusRing: string; maskBg: string;
  success: string; warning: string; danger: string; info: string;
}

interface UserTheme {
  id: string; name: string; mode: "light" | "dark";
  version: 1; tokens: ThemeTokens; createdBy: string; updatedAt: string;
}

新建主题时填写名称、亮/暗基底与主色。系统自动派生 hover、active、soft、border 等色阶；高级配置允许覆盖 Token，但不能删除 Token。

同文档模块联邦子应用

常规模块联邦子应用与 Shell 位于同一个 document，根节点 CSS 变量可天然继承。页面只要使用 var(--g2-*)，不需要逐个 postMessage。 

:root {
  --g2-color-primary: #1677ff;
  --g2-color-page-bg: #f5f7fa;
  --g2-color-surface-bg: #ffffff;
  --g2-color-text: rgb(0 0 0 / 85%);
  --g2-color-border: #d9d9d9;
}

必须订阅事件的场景

  • ECharts、Canvas、地图、播放器等初始化时读取颜色的组件；
  • Teleport 到 body 且存在局部变量覆盖的组件；
  • 直接独立启动的子应用；
  • iframe 遗留子应用。
主题契约包建议新建只读包 @g2-platform/theme-contract，提供 getTheme() 与 subscribeTheme(listener)。子应用不得反向依赖 pc-chrome。iframe 发送完整主题对象，目标 origin 必须白名单校验，逐步替换当前 "*" 的临时路径。

Ant Design 与遗留应用

  • pc-ui 的 ZhConfigProvider 接收 Token 并写入 Ant Design 主色、圆角与中性色。
  • CSS Modules 使用 G2 语义变量，不依赖 Ant Design 内部变量名。
  • 主题服务继续生成 --cube-theme-var--primary-*，兼容 Ant Design 3 / LESS 遗留应用。
  • 输入框、表格、Modal、Popover、Dropdown、DatePicker、Pagination、Tabs 的覆盖集中在 pc-ui。

5. 页面编码规范

允许

.page { background: var(--g2-color-page-bg); }
.card { background: var(--g2-color-surface-bg); color: var(--g2-color-text); }
.hint { color: var(--g2-color-text-secondary); }
.danger { color: var(--g2-color-danger); }

禁止

/* 禁止在业务页面硬编码通用颜色 */
background: #fff;
color: #1677ff;
border-color: #d9d9d9;

业务图表与告警等级只能消费受控的 chartSeries*、alarmLevel* Token；图片、视频、品牌 Logo、第三方地图底图不纳入主题替换。

6. 用户操作与接口需求

主应用功能

  1. 主题设置弹窗显示内置主题和“新建主题”。
  2. 新建主题填写名称、亮/暗模式、主色，并实时预览按钮、输入框、表格与弹窗。
  3. 高级面板编辑背景、文字、边框和状态色；保存前校验格式与对比度。
  4. 主题可设为仅自己使用或租户默认主题（后者需要权限）。
  5. 支持复制、编辑、删除自定义主题；内置主题不可删除。
  6. 选择主题后立即生效并自动持久化，刷新和重新登录后恢复。

接口建议

接口 用途
GET /ui-themes 获取当前用户可用主题列表与租户默认主题。
GET /ui-themes/current 获取当前用户生效主题，应用启动前加载。
POST /ui-themes 创建用户主题。
PUT /ui-themes/:id 更新用户主题。
DELETE /ui-themes/:id 删除用户自定义主题。
PUT /ui-themes/current 设置当前用户主题。
PUT /tenant/ui-theme 设置租户默认主题，需要管理员权限。

接口返回完整 UserTheme 与 version，保证后续 Token 扩展兼容旧数据。

7. 安全性与可访问性

  • 仅接受标准 CSS 色值；前后端均校验，禁止任意 CSS 片段。
  • textOnPrimary 与主色对比度低于 WCAG AA 4.5:1 时，拒绝保存或提供修正色。
  • text/pageBg、text/surfaceBg、placeholder/inputBg、danger/surfaceBg 也须做对比度校验。
  • 深色模式必须覆盖禁用态、边框、空状态、遮罩、日期面板与表格滚动区域。
  • 主题切换不改变状态颜色业务含义，除非用户在高级设置明确启用状态色覆盖。

8. 分阶段实施

1. 主题内核主题契约、完整 Token、主应用 applyTheme()。
2. 通用组件pc-ui ConfigProvider 与基础控件统一覆盖。
3. Chrome 与安防域替换当前审计范围的背景、文字、边框及主色。
4. 其他领域批量迁移并建立新增页面使用 Token 的规则。
5. 遗留 iframe以完整主题对象消息桥接，实现无需刷新同步。
6. 后端个性化用户/租户 CRUD、权限与跨会话恢复。

9. 自动化约束与验收

按现有协作约定，后续页面改动不要求逐页人工界面验收；主题系统必须具备以下自动化保障：

  1. applyTheme() 单元测试：覆盖所有必填 CSS 变量、Ant Design 色板与持久化数据。
  2. Token Schema 测试：缺失 Token、非法颜色、低对比度主题不能保存。
  3. 主题契约测试：模块联邦子应用可读取当前主题并收到 g2:theme-change。
  4. 静态扫描：业务目录出现未豁免的 #fff、#1677ff、#d9d9d9 等通用硬编码颜色即失败。
  5. 例外白名单：Logo、图片、视频、业务告警等级、图表固定序列必须注明原因与 Token 归属。

10. 决策

采用“主应用集中定义 + CSS 变量天然继承 + 事件补充同步 + 子应用只消费契约”模式。
禁止为每个应用维护多套主题 CSS，禁止按主题名称判断颜色，禁止子应用独立保存主题状态。
