# 客制覆盖粒度按部署形态分层，暂不给 Composition Profile 加 tenant 字段

本仓库部署目标既有 SaaS（一套运行时实例服务多个客户）也有私有化部署（每个客户独立一套部署实例），客制覆盖的粒度因此分三层：私有化部署天然隔离，整套部署实例本身即服务单一客户，不需要任何运行时区分机制；SaaS 下目前只有系统级客制需求（同一环境对所有租户统一生效），复用 ADR-0043 的版本注册表指针替换机制即可；SaaS 内的租户级细粒度客制（同一环境只对部分租户生效）暂无真实需求，留作未来扩展。

因此 Composition Profile 暂不引入 `tenant` 维度——源 Profile 保持「圈选范围，不感知租户」，租户身份（如来自子域名等鉴权前静态信息）只会在未来影响版本注册表的查表方式，不进入 Profile schema。若未来真的要支持租户级客制，需要重新评估注册表 key 是否要从「环境 + 逻辑名」扩展为「环境 + 租户 + 逻辑名」，以及门面在鉴权前基于静态信息识别租户身份的具体机制（如登录页本身的客制）。
