# 浏览器崩溃/错误采集自建钩子，不引入 Sentry 类三方 SDK

浏览器端错误上报/崩溃收集不接入 Sentry 等三方监控 SDK 作为独立采集入口，而是在 `window.onerror` / `unhandledrejection` 上自建钩子，钩子内部调用 logger 自身接口（如 `logger.error`），复用同一套日志语义与（未来的）上报通道，不让崩溃采集另起一套并行体系。这偏离了多数团队"崩溃监控直接上 Sentry"的默认路径：换来的是采集入口收敛到一个自建通道，不为此新增一个独立三方依赖与一套平行的配置/上报目标；代价是放弃了 Sentry 类工具自带的源码映射还原、面包屑、会话回放等成熟能力，后续如需要这些能力需要自行实现或重新评估。
