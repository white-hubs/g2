# 响应异常统一封装为标准异常类上抛；副作用是否触发由业务层决定，登出动作走 ctx.bus 通知 Shell

用语随 ADR-0057：「分域 client」读作 **服务 Client**（按服务面，非 UI 包内模块）。本 ADR 的错误上抛与副作用边界不变。

`@g2-platform/http` / 服务 Client 遇到失败响应时，统一抛出一种标准化的异常类（延续旧仓 `standard/infrastructure/gateway` 里 `ServiceErrorFactory` 已经做对的错误归一化思路——兼容新旧两种后端错误 JSON 形状，统一成一套 `errorCode`/`errorMessage`/`errorDetail` 结构），调用方不需要自己判断响应形状是新是旧。

但具体错误码要不要触发全局副作用（如 401 强跳登录页），**不由 http 客户端或服务 Client 统一拍板**——同样是 401，是否代表会话失效、要不要强制登出，取决于具体业务/接口语境（并非所有 401 场景都等价于会话过期），因此决定权在服务 Client 之上的业务层（调用方）：Client 只负责把标准异常原样上抛，不吞、不加自己的判断逻辑。当业务层判断确实需要触发登出时，通过 `ctx.bus` 广播一个事件通知 Shell 执行真正的登出（token 清除、路由跳转完全在 Shell 内部完成，符合 ADR-0028 鉴权状态机不下放的边界），复用 ADR-0030 已经建立的总线机制——此前总线只用于 Shell → pc-messaging/pc-rtc 方向的通知（登出/重载回调），这次新增业务层 → Shell 方向的用法，是同一条总线的双向使用，不新增独立通道。
