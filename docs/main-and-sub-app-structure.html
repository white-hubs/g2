主应用与子应用
结构说明

本文用于快速定位 g2 项目中的 PC 主应用、业务子应用及其组装配置，并说明几个相邻目录各自承担的职责。

01

主应用在这里

apps/shells/pc，项目术语称为 PC Shell（PC 门面）。

02

子应用在这里

apps/domains/*，项目术语称为 Domain（业务域）。

Directory map

目录定位

g2/
├── apps/
│   ├── shells/
│   │   └── pc/                       ← 主应用（Shell / MF Host）
│   │       ├── index.html             ← 浏览器 HTML 入口
│   │       └── src/
│   │           ├── main.ts            ← 启动与组装入口
│   │           └── App.tsx            ← 根组件
│   ├── domains/
│   │   ├── access-control/           ← 正式业务域
│   │   ├── poc-remote-pc/             ← Remote Domain 示例
│   │   └── poc-inline-pc/             ← Inline Domain 示例
│   ├── platforms/                     ← 平台能力，不是业务子应用
│   ├── page-libraries/                ← 可复用页面库
│   └── clients/                       ← 服务 Client remote
└── deploy/
    └── compositions/
        └── prod.pc.yaml               ← 主应用组装清单

Main application

主应用：PC Shell

物理位置与入口

主应用位于 apps/shells/pc。

  • index.html：Vite 提供的浏览器入口。
  • src/main.ts：创建 Vue 应用、路由和 Pinia，并执行启动编排。
  • src/App.tsx：主应用根组件。

它负责什么

  • 管理鉴权状态、路由表和整体框架布局。
  • 读取已解析的 Composition Profile。
  • 装载 Domain、Platform、页面库和服务 Client。
  • 迁移期间兼容装载外部 qiankun 旧微应用。

Business domains

子应用：Domain

目录 类型 主要入口 说明
apps/domains/access-control 正式业务域 src/domain.ts 通过 Module Federation 暴露 ./domain，由 Shell 动态装载。
apps/domains/poc-remote-pc 远程示例 src/domain.ts 演示独立构建、运行时加载的 Remote Domain。
apps/domains/poc-inline-pc 内联示例 src/domain.ts 作为工作区依赖直接进入 Shell，不经远程地址加载。

Runtime composition

主应用如何装载子应用

STEP 01 浏览器进入 Shell

index.html 加载 src/main.ts。

STEP 02 读取组装配置

Shell 获取部署时生成的 resolved profile。

STEP 03 解析模块清单

识别 inline、remotes 等槽位。

STEP 04 注册 Domain 路由

业务域被挂载到 Profile 指定的 basePath。

!

仓库内的源组装清单是 deploy/compositions/prod.pc.yaml。其中 inline 声明内联域，remotes 声明远程域；生产运行时读取的是由该清单和版本注册表解析得到的 JSON，而不是直接读取 YAML。

Responsibility boundaries

这些目录不是“子应用”

目录 职责 与 Domain 的区别
apps/platforms/* 提供鉴权、UI、日志、地图、消息等平台能力。 通常没有独立业务路由，不是对外导航的业务单元。
apps/page-libraries/* 提供可被多个业务域复用的页面或组件。 不拥有对外 URL，需要由 Domain 挂到自己的路由中。
apps/clients/* 封装不同服务面的请求、类型与调用接口。 属于数据访问层，不提供业务页面。
外部 qiankun 应用 迁移期保留的旧微应用。 源码不在当前 Domain 目录中，由 Shell 按运行时配置从外部加载。

Conclusion

一句话结论

✓

主应用位于 apps/shells/pc，业务子应用位于 apps/domains/*； 二者的装载关系由 deploy/compositions/prod.pc.yaml 描述。项目文档中更推荐使用 “Shell（门面）”和“Domain（业务域）”这两个术语。

依据仓库目录、PC Shell 入口、Module Federation 配置及 Composition Profile 整理。
